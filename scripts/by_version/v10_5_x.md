# v10.5.x 脚本归纳

V10.5.x 覆盖机构级研究操作台、席位竞争仲裁，以及 V10.5.3 的执行策略长期反馈画像。

## 正式迁移脚本

- `../migrations/upgrade_to_v10_5_1.py`：V10.5.1 升级
- `../migrations/upgrade_to_v10_5_2.py`：V10.5.2 升级
- `../migrations/upgrade_to_v10_5_3.py`：V10.5.3 升级（创建 `execution_policy_profiles`）
- `../migrations/upgrade_to_v10_5_4.py`：V10.5.4 升级（补齐 `trading_signals.signal_origin_mode` 与查询索引）

## V10.5.3 回补 / 修复脚本

- `../migrations/backfill_execution_policy_profiles.py`：从 `execution_quality_log` + `autonomous_execution_intent` 回填执行画像；默认 dry-run，`--execute` 真正写入。
- `../maintenance/repair_execution_policy_profiles.py`：检查并修复 stale / orphan / missing / duplicate 画像键；默认 dry-run，`--execute` 真正修复。
- `../maintenance/execution_policy_profile_common.py`：供回填与修复脚本复用的聚合逻辑。

## V10.5.4 回补 / 修复 / 验收脚本

- `../maintenance/backfill_signal_integrity_v10_5_4.py`：回补 `signal_origin_mode`、canonical `signal_payload`、native `signal_transitions`；默认 dry-run，`--apply` 真正写入。
- `../maintenance/repair_signal_integrity_v10_5_4.py`：检查并修复 signal integrity 不一致（origin mode / payload version / transition 缺失）；默认 dry-run，`--apply` 真正修复。
- `../checks/_acceptance_v10_5_4.py`：V10.5.4 验收脚本，检查 schema、feature flags、payload/version、truth source 与 native transition reader。

## 推荐执行顺序

1. 先运行 `../migrations/upgrade_to_v10_5_3.py --check`
2. 若目标表不存在，再执行 `../migrations/upgrade_to_v10_5_3.py`
3. 执行 `../migrations/backfill_execution_policy_profiles.py`（先 dry-run，再 `--execute`）
4. 执行 `../maintenance/repair_execution_policy_profiles.py`（先 dry-run，再 `--execute`）
5. 执行 `../migrations/upgrade_to_v10_5_4.py --check`
6. 若缺列 / 缺索引，再执行 `../migrations/upgrade_to_v10_5_4.py`
7. 执行 `../maintenance/backfill_signal_integrity_v10_5_4.py`（先 dry-run，再 `--apply`）
8. 执行 `../maintenance/repair_signal_integrity_v10_5_4.py`（先 dry-run，再 `--apply`）
9. 执行 `../checks/_acceptance_v10_5_4.py`

## 说明

- 两个回补/修复脚本都支持 `--account-id`，可先针对单账户灰度执行。
- 推荐在运行前先备份数据库。
- `repair_execution_policy_profiles.py` 设计为可重复执行，适合作为上线后数据巡检辅助脚本。
- V10.5.4 的 signal integrity 脚本同样支持小窗口 / 单账户灰度，建议先 `OBSERVE → SHADOW → SEMI → FULL` 分阶段 rollout。
